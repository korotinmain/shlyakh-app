# XP and Level Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pure Dart domain functions that turn daily steps into XP and XP into levels, exactly as the spec's tables define, with 100% coverage.

**Architecture:** Two files in `lib/features/progress/domain/`: `xp_rules.dart` (daily and total XP) and `level_curve.dart` (thresholds, level progress). No Flutter, no Clock, no IO. Table-driven unit tests mirror `lib/` under `test/`.

**Tech Stack:** Dart 3.13 (`new(...)` constructors, records), flutter_test.

**Spec:** `docs/superpowers/specs/2026-09-27-xp-rules-design.md`

## Global Constraints

- Branch `feat/xp-rules`; Conventional Commits ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Domain files import nothing but `dart:core` (AGENT_RULES, CLAUDE.md "Domain layer is pure Dart").
- Integer arithmetic only; no `double` anywhere in the rules.
- Invalid input throws `ArgumentError` (negative steps, level < 1, negative total XP). No clamping, no silent fallback.
- Values are exactly the spec's tables: daily XP rows, level thresholds 1–27, continuation step 81 600.
- Gate before each commit: `dart format --output=none --set-exit-if-changed . && dart analyze --fatal-infos && flutter test --coverage && dart run tool/coverage/check_coverage.dart`. Domain coverage must be 100%.
- Commits on a feature branch; the Stop hook runs analyze + test at the end of each turn with Dart changes.

## Review Focus

- XP never decreases when a day's steps grow (the product promise "no XP ever lost"): `dailyXp` is non-decreasing for every steps value 0…40 000. Test in Task 1.
- A far-future total (ten years at the daily cap: 3 650 × 20 000 = 73 000 000 XP) yields the right continuation level without iterating per level. Test in Task 2.
- Every threshold round-trips: `levelProgress(xpToReachLevel(n)).level == n` and one XP less gives `n − 1`, for n = 2…60. Test in Task 2.
- `xpForNextLevel` never jumps at the main-path/continuation seam (levels 24, 25, 26 all 81 600). Test in Task 2.
- A total exactly at `mainPathXp` is level 25 with 0 XP into it, not level 24 at 100%. Test in Task 2.

group('dailyXp', () {
  final cases = <(int steps, int xp)>[
    (0, 0), (500, 500), (10000, 10000), (10001, 10000), (10002, 10001),
    (25000, 17500), (30000, 20000), (500000, 20000),

  }
  test('rejects negative steps', () =>
      expect(() => dailyXp(-1), throwsArgumentError));
  test('never decreases as steps grow', () {

      expect(dailyXp(s), greaterThanOrEqualTo(dailyXp(s - 1)), reason: 's=$s');
    }
  });

  test('sums daily XP', () => expect(totalXp(const [500, 6000, 25000]), 24000));
  test('applies the cap per day', () => expect(totalXp(const [500000, 500000]), 40000));
  test('rejects a negative day', () =>
      expect(() => totalXp(const [100, -1]), throwsArgumentError));
});

### Task 2: Level curve

**Files:**
- Create: `lib/features/progress/domain/level_curve.dart`
- Test: `test/features/progress/domain/level_curve_test.dart`

**Interfaces:**
- Produces (exactly as the spec's Domain API):
  - `const mainPathLevels = 25;`, `const mainPathXp = 1000000;`
  - `int xpToReachLevel(int level)` — level 1 → 0; 2…25 → `(1000000 * (level - 1)^2 + 28800) ~/ 57600 * 100`; above 25 → `mainPathXp + (level - 25) * continuationStep`, where `continuationStep = xpToReachLevel(25) - xpToReachLevel(24)` (81 600).
  - `typedef LevelProgress = ({int level, int xpIntoLevel, int xpForNextLevel});`
  - `LevelProgress levelProgress(int totalXp)` — below `mainPathXp`: highest main-path level whose threshold ≤ totalXp (at most 25 checks); at or above: `25 + (totalXp - mainPathXp) ~/ continuationStep` (constant time).
  - `bool isOnMainPath(int level)` — `level <= mainPathLevels`.

- [ ] **Step 1: Write the failing tests**
  - `xpToReachLevel` table: all 27 rows of the spec's Levels table as `(level, xp)` cases; `'rejects level 0'` → `throwsArgumentError`; `'computes a far continuation level'`: level 100 → `7120000`.
  - `levelProgress` boundaries, each asserting the whole record:
    - 0 → `(level: 1, xpIntoLevel: 0, xpForNextLevel: 1700)`
    - 1699 → `(level: 1, xpIntoLevel: 1699, xpForNextLevel: 1700)`
    - 1700 → `(level: 2, xpIntoLevel: 0, xpForNextLevel: 5200)`
    - 999999 → `(level: 24, xpIntoLevel: 81599, xpForNextLevel: 81600)`
    - 1000000 → `(level: 25, xpIntoLevel: 0, xpForNextLevel: 81600)`
    - 1081599 → `(level: 25, xpIntoLevel: 81599, xpForNextLevel: 81600)`
    - 1081600 → `(level: 26, xpIntoLevel: 0, xpForNextLevel: 81600)`
    - 73000000 → `(level: 25 + 72000000 ~/ 81600, xpIntoLevel: 72000000 % 81600, xpForNextLevel: 81600)` i.e. level 907, xpIntoLevel 28 800
    - −1 → `throwsArgumentError`
  - `'round-trips every threshold'`: for n in 2…60, `levelProgress(xpToReachLevel(n)).level == n` and `levelProgress(xpToReachLevel(n) - 1).level == n - 1`.
  - `'thresholds strictly increase'`: n in 2…60.
  - `isOnMainPath`: 25 → true, 26 → false, 1 → true.
